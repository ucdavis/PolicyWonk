# Initial model comparison — September 21, 2026

**Recommendation: keep gpt-5.2 under the current prompt.** Terra is faster, but
neither tested reasoning setting cleared the grounding and uncertainty comparison.
Medium reasoning did not show a convincing advantage over low. Tighten the
prompt's evidence-only answering and clarification behavior, address retrieval
coverage/freshness, then rerun before a model switch.

This file contains aggregate results only. Production questions, answers, source
snapshots, and review notes are private local artifacts and are not committed.
Production remained read-only; no model setting or deployment was changed.

## Dataset and method

- Latest 100 approved distinct saved production questions, September 9–21, plus
  10 synthetic edge cases; case/whitespace deduplication preserves focus.
- Examined 133 chats for 130 review candidates: skipped two greetings/short
  questions and one identifier match. Local review discarded three more questions
  containing personal names/correspondence or personal family medical details.
  No rejected question was used in generation, embeddings, or judging.
- Scope: 92 core, nine union, five Knowledge Base, three APM, one UCOP cases
  including the synthetic set. Similar rewordings remain; this is an exploratory
  recent-query benchmark, not a representative traffic sample.
- Current app retrieval/prompt/citation code from main `5be4534`, production index
  and full-document lookups, production embedding model, test API key, US endpoint.
  Every variant received the same frozen question and merged policy context.
- Compared gpt-5.2 medium, gpt-5.6-terra medium, and gpt-5.6-terra low. The baseline
  uses current code's medium reasoning; this is not a measurement of the older
  deployed production build's low-reasoning setting.
- One final answer per variant/case, 8,192 output-token cap, five concurrent cases.
  Completed **330/330 answers and 220/220 blinded comparisons**, with no final-run
  API failures, truncations, or invalid citation numbers.
- Fixed gpt-5.6-sol low judge, shuffled A/B order, exact merged evidence and citation
  catalog. Criteria: relevance, completeness, grounding, citation support, uncertainty.

## Quality comparison

Each row is the candidate against the same gpt-5.2 answer.

| ------------ | ------------------------------- | ------------------------------ |
| Terra medium | 25 / 24 / 51                    | 3 / 1 / 6                      |
| Terra low    | 23 / 28 / 49                    | 4 / 2 / 4                      |

Automated scores are not gold labels. Grounding averaged 4.62 versus 4.18 for
5.2 versus Terra medium, and 4.61 versus 4.29 for 5.2 versus Terra low. Uncertainty
handling also favored 5.2. Citation-number validity was perfect for all three,
but that does not mean the cited documents supported every claim.

Codex checked all **35 unique judge-flagged severe cases** and **10 seeded random
cases** against the frozen sources (42 distinct cases total). This was an
assistant source-based review, not a human policy-owner validation. Several severe
labels were overstated: generic security advice or carefully qualified suggestions
were sometimes treated as serious policy errors. The private report records those
disagreements rather than presenting raw severe counts as confirmed defects.

The substantive concern survives that review: Terra sometimes supplied unsupported
specific definitions, job-code mappings, or permissions instead of acknowledging
missing evidence. In one case the two Terra settings assigned different rank
mappings to the same job codes, none of which appeared in the supplied sources.
5.2 had its own failures, including misapplying a non-exempt meal-rule answer to an
exempt-employee question. A model change alone does not solve these issues.

Reversing A/B order on 12 disputed/important cases preserved the winner in **20 of
24 comparisons**. Four results flipped, confirming that close judge decisions
should not be treated as precise truth. This checks judge/order stability, not
model generation variability. No settings were tuned on this benchmark.

## Retrieval findings

All five sampled Knowledge Base questions returned zero documents. A read-only
production source-type aggregation confirmed **zero UCDKB chunks** in the selected
index. Other cases retrieved old payroll procedures or contract provisions ending
before the years asked about. Different answer models cannot supply missing or
current policy evidence reliably. These gaps should be investigated independently.

## Reuse and cost of the evaluation

The runner retains the reviewed dataset and frozen contexts, resumes cached model
calls, and separates generation fingerprints from judge changes. See [README](README.md)
for sample, prepare, run, recheck and report commands. Updating the benchmark still
requires a fresh privacy review.

Recorded/estimated usage for the pilot, evaluator checks, final comparison and
rechecks was **$29.82**, plus **$4.23**
conservatively reserved for interrupted setup calls: **$34.05**
total budget accounting, below the $50 cap. This is not an invoice. The final
comparison's three answer sets together cost about $6.08; most remaining expense
was judging and evaluator validation. Initial judge versions were superseded to
match the app's merged citation numbering and generated citation metadata; those
versions are excluded from quality results. Completed answers were reused after
verifying that the generation function and request parameters were unchanged.

Validation: eight Node tests, three Python privacy-filter tests, live 110-case
replay, report rendering/filter checks, read-only database-session confirmation,
and identifier screening of the final dataset.
